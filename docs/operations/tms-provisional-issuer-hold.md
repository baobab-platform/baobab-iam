## Security corrections required by the final-head gates

All root and nested CP-consumer modules use checksum-verified JOSE 4.1.6 for GHSA-mgcc-cww5-fp2q. The isolated Hydra audience candidate also migrates Hydra, Fosite and Oryx types consistently from unsupported v3 to v4.1.6. Its reproducible patch applies only after the exact upstream audience, existing dependency-security and HTTP regression patches. JWT builder APIs and explicit parsing algorithm lists preserve existing verification semantics; the generic upstream wrapper's explicit unsafe-none-key behavior is unchanged, while RFC7523 parsing never permits none. Unit tests, upstream RSA/private-header regressions, actual native build, JWT-bearer HTTP integration, SBOM and strict image scan remain required. No v3 JOSE module may remain in the candidate runtime dependency closure. The build receipt includes the patch digest, module version and native binary/source digests. This remains a development candidate, never a production Hydra promotion.

The pinned Keycloak 26.7.5 base remains unchanged. Its affected Guava dependency is replaced before augmentation by canonical Maven `com.google.guava:guava:33.7.2-jre`, SHA256 `b530942257fb935f8b2cfaa5f8eb5bd59c555fd8e8d01b8ce98912e077ea606c`. The build fails if the expected single upstream Guava jar changes. Download tooling is confined to a discarded build stage. Strict image scans, Keycloak baseline and integration variants must pass; no CVE ignore, VEX exception or production deployment is introduced.
